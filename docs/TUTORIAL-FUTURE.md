# 튜토리얼 (미래) — 블로그 만들기

> **아직 없는 프레임워크의 튜토리얼입니다.** v0이 완성됐을 때 이런 모습이면 좋겠다는 그림입니다.
> 흐름은 [DECISIONS.md](DECISIONS.md)를 따르지만, 함수 이름·명령 이름·출력 모양은 대부분 아직
> 정해지지 않았습니다. 본문에서 🔮 표시가 붙은 곳이 가정이고, 끝의 [가정 목록](#가정-목록)에 모았습니다.
> 구현하면서 이 문서가 틀렸다고 밝혀지면, 문서를 고칩니다.

---

## 들어가며

이 튜토리얼에서는 작은 블로그를 만듭니다. 글을 쓰고, 목록을 보고, 글 하나를 읽고, 관리자 화면에서
글을 고치는 데까지 갑니다.

Maago를 쓰는 사람은 보통 사람이 아니라 **에이전트**입니다. 그래서 이 튜토리얼에는 일부러 틀리는
단계가 들어 있습니다. Maago가 무엇을 잡아 주는지, 오류 메시지가 어떻게 생겼는지 보는 것이
이 튜토리얼의 절반입니다.

필요한 것:
- Go 1.25 이상
- 터미널

---

## 1. 설치

```sh
go install github.com/maago-web/maago/cmd/maago@latest
maago help
```

## 2. 프로젝트 만들기

Maago 프로젝트는 그냥 Go 모듈입니다. `maago new`는 아직 없으니(v1) 손으로 만듭니다.

```sh
mkdir myblog && cd myblog
go mod init example.com/myblog
go get github.com/maago-web/maago
```

DB는 `.env`에 적습니다. 처음에는 SQLite가 편합니다.

```sh
# .env
MAAGO_DATABASE_URL=sqlite:app.db
```

> `.env`는 커밋하지 않습니다. `.gitignore`에 넣어 두세요.

## 3. 앱 만들기 — 모델

Maago의 앱은 Go 패키지 하나입니다. 등록 파일은 없습니다. `blog/` 디렉터리를 만들고 모델을 씁니다.

```go
// blog/models.go
package blog

import (
	"time"

	"github.com/maago-web/maago"
)

type Post struct {
	maago.Model `maago:"table=posts,ordering=-PublishedAt"`

	ID          int64      // 🔮 이름이 ID인 int64 필드가 PK
	AuthorID    int64      `maago:"fk=auth.User,label='글쓴이'"`
	Title       string     `maago:"max=200,label='제목'"`
	Text        string     `maago:"label='본문'"`
	Status      string     `maago:"max=20,choices=draft/published,default='draft',label='상태'"`
	PublishedAt *time.Time `maago:"label='게시일'"` // 🔮 포인터면 NULL 허용
}
```

읽는 법:
- 모든 설정은 `maago:"…"` 태그 안에 있습니다. 옵션은 `,`로 나누고, 문자열은 `'…'`로 감쌉니다.
- 테이블 이름이나 정렬처럼 모델 전체에 대한 설정은 임베드한 `maago.Model`의 태그에 씁니다.
- 관계는 객체가 아니라 **ID 필드 + `fk=모델`** 입니다. 글쓴이의 이름이 필요하면 SQL에서 JOIN합니다.
  몰래 나가는 쿼리는 없습니다.
- `choices=draft/published`처럼 선택지는 `/`로 나눕니다.

### 일부러 틀려 보기

`max`를 `maxlen`으로 잘못 써 봅시다.

```go
	Title       string     `maago:"maxlen=200,label='제목'"`
```

```sh
maago gen
```

```
blog/models.go:15:33: unknown tag key "maxlen" in Post.Title
  fix: did you mean "max"? allowed: max, min, unique, index, default, choices, fk, label, help
```

Maago의 오류는 언제나 이 모양입니다. **위치, 무엇이 틀렸는지, 어떻게 고치는지.** 경고는 없고
오류만 있습니다. 오류가 하나라도 있으면 `maago gen`은 파일을 하나도 쓰지 않습니다.

`max`로 되돌리고 다시 돌리면 `blog/models_gen.go`가 생깁니다. 첫 줄에
`// Code generated by maago. DO NOT EDIT.`이 있는 파일은 손대지 않습니다. 생성 파일도 커밋합니다.

## 4. 마이그레이션

모델이 DB의 원천입니다. 모델을 보고 마이그레이션 초안을 만듭니다.

```sh
maago makemigrations
```

```
created migrations/0001_initial.sql
```

```sql
-- migrations/0001_initial.sql
-- (auth 앱의 테이블은 생략)

CREATE TABLE posts (
    id           INTEGER PRIMARY KEY,
    author_id    INTEGER NOT NULL REFERENCES auth_user (id),
    title        VARCHAR(200) NOT NULL,
    text         TEXT NOT NULL,
    status       VARCHAR(20) NOT NULL DEFAULT 'draft'
                 CHECK (status IN ('draft', 'published')),
    published_at TIMESTAMP
);
```

이 파일은 **초안**입니다. 주인은 여러분이고, 손으로 고쳐도 됩니다. Maago는 이전 상태를 따로 기록하지
않습니다. 마이그레이션을 연습용 DB에 적용해 본 결과가 곧 이전 상태이고, 그 결과가 모델과 같은지를
`maago check`가 확인합니다.

적용합니다.

```sh
maago showmigrations
maago migrate
```

### 필드 이름을 바꾸면

`Text`를 `Body`로 바꾸고 `makemigrations`를 돌리면, Maago는 “이름 변경인가요?”라고 묻지 않습니다
(에이전트는 `[y/N]`에 답하지 못합니다). 대신 초안에 ⚠ 경고와 대안 SQL을 적습니다. 이름 변경이 맞다면
이렇게 알려 줍니다.

```sh
maago makemigrations --rename posts.text:body
```

컬럼을 지우는 `DROP`이 들어간 마이그레이션은, 파일 안에 `-- maago: allow-drop`을 적어야
`check`를 통과합니다. 실수로 데이터를 지우지 않게 하려는 장치입니다.

## 5. 관리자 화면과 로그인

여기까지 오면 관리자 화면이 생깁니다. admin은 모델에서 생성된 코드만 쓰고, 로그인한 사용자만
들어갈 수 있습니다.

```go
// main.go
package main

import (
	"log"
	"net/http"

	"github.com/maago-web/maago"
	_ "github.com/maago-web/maago/contrib/admin"
	_ "github.com/maago-web/maago/contrib/auth"

	_ "example.com/myblog/blog"
)

func main() {
	log.Fatal(http.ListenAndServe(":8000", maago.Handler())) // 🔮
}
```

앱은 blank import로 등록합니다. 관리자 계정을 만들고 서버를 켭니다.

```sh
maago createsuperuser   # 🔮
go run .
```

<http://localhost:8000/admin/>에서 로그인하면 글 목록·쓰기·고치기·지우기가 됩니다.

> 필드 이름이 `password`라고 admin이 알아서 숨기지는 않습니다. 숨기고 싶으면 태그로 말합니다.
> Maago는 이름으로 추측하지 않습니다.

**여기까지가 Maago v0의 목표입니다: 모델 → makemigrations → migrate → admin + 로그인, 5분.**

## 6. SQL 쓰기

Maago에는 ORM이 없습니다. SQL은 파일에 손으로 씁니다. 대신 Maago가 그 SQL을 연습용 DB에
미리 돌려 보고 검사합니다.

```sql
-- blog/queries/published_posts.sql
-- name: PublishedPosts :many Post
SELECT id, author_id, title, text, status, published_at
FROM posts
WHERE status = 'published'
ORDER BY published_at DESC
```

머리의 `:many Post`는 “여러 줄, 결과 타입은 `Post`”라는 뜻입니다. 결과 타입이 모델 이름이면
**모든 컬럼이 맞아야** 합니다. 컬럼을 하나 빼 보면:

```
blog/queries/published_posts.sql:3:1: result columns do not match model Post: missing "published_at"
  fix: select every column of Post, or declare a new result type name (e.g. ":many PostSummary")
```

일부만 채운 `Post`를 저장했다가 데이터가 지워지는 일을 막기 위해서입니다. 필요한 컬럼만 원하면
새 이름을 주면 됩니다. 그 모양의 struct를 Maago가 만들어 줍니다.

검색처럼 조건이 있다 없다 하는 쿼리는 `{ }`로 씁니다.

```sql
-- blog/queries/search_posts.sql
-- name: SearchPosts :many PostSummary
-- param: q?       string
-- param: status?  string
SELECT id, title, published_at
FROM posts
WHERE {
  {q}        AND title LIKE '%' || :q || '%'
  {status}   AND status = :status
  {!status}  AND status = 'published'
}
ORDER BY published_at DESC
```

- `:q`는 값 바인딩입니다. `q?`의 `?`는 “없어도 된다”는 뜻입니다.
- 줄 앞의 `{q}`는 “`q`가 있을 때만 이 줄을 넣는다”입니다.
- `WHERE { }` 안에서는 맨 앞의 `AND`를 Maago가 정리하고, 다 비면 `WHERE` 자체를 없앱니다.

`maago gen`을 돌리면 Maago는 가능한 조합을 전부 연습용 DB에 prepare해 봅니다. 생성된 함수는
대략 이렇게 생겼습니다.

```go
// blog/queries_gen.go (생성됨) 🔮
func PublishedPosts(ctx context.Context, db maago.DB) ([]Post, error)
func SearchPosts(ctx context.Context, db maago.DB, p SearchPostsParams) ([]PostSummary, error)
```

## 7. URL과 뷰

라우트는 표 하나에 모읍니다.

```go
// blog/urls.go
package blog

import "github.com/maago-web/maago"

var Routes = maago.Routes{
	maago.GET("/", "post_list", PostList),
	maago.GET("/post/{id}", "post_detail", PostDetail),
}
```

뷰는 `http.ResponseWriter`를 받지 않습니다. 들어오는 값과 나가는 값이 타입으로 정해져 있고,
요청을 해석하고 템플릿을 그리는 코드는 Maago가 생성합니다.

```go
// blog/views.go
package blog

import (
	"context"

	"github.com/maago-web/maago"
)

type PostListPage struct {
	Posts []Post
}

func PostList(ctx context.Context, in struct{}) (PostListPage, error) {
	posts, err := PublishedPosts(ctx, maago.DBFrom(ctx)) // 🔮
	return PostListPage{Posts: posts}, err
}

type PostDetailIn struct {
	ID int64 `maago:"path=id"` // 🔮
}

type PostDetailPage struct {
	Post Post
}

func PostDetail(ctx context.Context, in PostDetailIn) (PostDetailPage, error) {
	post, err := GetPost(ctx, maago.DBFrom(ctx), in.ID) // GetPost: PK 기준 CRUD는 생성된다
	return PostDetailPage{Post: post}, err
}
```

`/post/abc`처럼 해석할 수 없는 값이나, 글이 없어서 나온 `sql.ErrNoRows`는 404가 됩니다.

## 8. 템플릿

템플릿은 Go 표준 `html/template`입니다. 뷰가 돌려주는 타입이 템플릿의 데이터 타입입니다.

```html
<!-- blog/templates/post_list.html -->
{{define "content"}}
  {{range .Posts}}
    <article>
      <h2><a href="{{url "post_detail" .ID}}">{{.Title}}</a></h2>
      <p>{{.PublishedAt}}</p>
    </article>
  {{end}}
{{end}}
```

```html
<!-- blog/templates/post_detail.html -->
{{define "content"}}
  <h1>{{.Post.Title}}</h1>
  <div>{{.Post.Text}}</div>
{{end}}
```

### 일부러 틀려 보기

`{{.Post.Title}}`을 `{{.Post.Titel}}`로, `post_detail`을 `post_detial`로 바꾸고 `maago gen`을 돌리면:

```
blog/templates/post_detail.html:3:7: PostDetailPage.Post has no field "Titel"
  fix: did you mean "Title"?
blog/templates/post_list.html:5:22: unknown route name "post_detial"
  fix: did you mean "post_detail"? routes are declared in blog/urls.go
```

두 오류가 **한 번에** 나옵니다. 하나 고치고 다시 돌리고, 또 하나 고치고 다시 돌릴 필요가 없습니다.
브라우저를 열기 전에 잡힙니다.

## 9. 폼 (맛보기)

글쓰기 폼도 태그에서 만들어집니다.

```go
// blog/forms.go
type PostForm struct {
	Title string `maago:"max=200,label='제목'"`
	Text  string `maago:"label='본문'"`
}
```

생성된 코드는 칸이 비어 있는 것, 숫자로 읽을 수 없는 것, 범위를 벗어난 것을 서로 다르게 알려 줍니다.
값을 조용히 버리지 않습니다.

## 10. 커밋하기 전에

```sh
maago check
```

`check`는 아무것도 쓰지 않고, 모든 검사를 돌리고, 생성 파일이 최신인지 봅니다. 생성 파일을 손으로
고쳤거나 `maago gen`을 잊었다면 실패합니다. CI에도 이 명령 하나를 넣으면 됩니다.

---

## 여기까지 한 것

- 모델은 struct와 `maago:"…"` 태그로 선언했습니다.
- 마이그레이션은 Maago가 초안을 쓰고, 우리가 확인했습니다.
- SQL은 손으로 썼고, Maago가 실행 전에 검사했습니다.
- 라우트·뷰·템플릿의 틀린 이름은 브라우저를 열기 전에 잡혔습니다.
- 모든 오류는 위치와 고치는 법을 함께 말했습니다.
