# 구현 루프

Maago는 에이전트가 만든다. 작업 하나(`TASKS-Mn.md`의 한 항목)는 아래 루프를 한 번 돈다.

```
 분석 ──▶ 계획 ──▶ 계획 리뷰 ──▶ 구현 ──▶ 테스트 ──▶ 구현 리뷰 ──▶ 완료
                     │                                │
                     └──────── 사람 판단이 필요하면 멈춘다 ────────┘
```

---

## 1. 분석

- `TASKS-Mn.md`의 작업과 `→ 확인:` 조건을 읽는다.
- 관련 결정(DECISIONS), 구조(ARCHITECTURE), 원칙(PHILOSOPHY)을 읽는다.
- 작업이 건드릴 코드를 끝까지 따라가 본다. 무엇을 바꿔야 하는지 알기 전에는 계획하지 않는다.

## 2. 계획

작업 항목 바로 아래에 `계획`을 적는다. 담을 것:

- 바꿀 파일과 새로 만들 파일
- 단계마다 `→ 확인:` (무엇을 돌려서 무엇을 보면 되는지)
- 결정에 없는 선택을 했다면 그 선택과 이유
- 하지 않기로 한 것

## 3. 계획 리뷰 — codex, fable

계획을 두 리뷰어에게 따로 보인다.

| 리뷰어 | 방법 | 보는 것 |
|---|---|---|
| **codex** | codex 플러그인 | 빠진 경우, 틀린 가정, 더 단순한 길 |
| **fable** | Claude Fable 모델 서브에이전트 | 결정·원칙과 어긋나는 곳, 확인 조건이 실제로 잡는지 |

- 지적은 받아들여 계획을 고치거나, 받아들이지 않는 이유를 계획에 한 줄로 적는다. 조용히 넘기지 않는다.
- 두 리뷰어의 의견이 갈리고 어느 쪽인지 결정으로 정해지지 않으면 **사람에게 묻는다.**

## 4. 구현

- 계획대로 만든다. 계획과 달라지면 계획부터 고친다.
- 버그를 고칠 때는 재현하는 테스트를 먼저 쓴다.
- 결정과 부딪히면 코드를 억지로 맞추지 않는다. 멈추고 DECISIONS를 고칠지 사람에게 묻는다.

## 5. 테스트

- 작업의 `→ 확인:` 조건을 전부 실제로 돌린다.
- `gofmt`, `go vet`, `go test`를 두 모듈 모두에서 돌린다.
- 게이트류 테스트(reflect 금지 등)는 일부러 어긴 코드를 넣어 **실패하는 것까지** 확인한다.

## 6. 구현 리뷰 — ponytail, codex, fable

| 리뷰어 | 보는 것 |
|---|---|
| **ponytail** | 과한 설계: 지울 수 있는 코드, stdlib로 바꿀 수 있는 것, 쓰이지 않는 추상화 |
| **codex** | 정확성: 버그, 빠진 경계 조건, 오류 처리. 테스트를 실제로 돌린다 |
| **fable** | 결정·원칙과의 일치, 테스트가 실제로 회귀를 잡는지 |

- 계획 리뷰와 같은 규칙: 고치거나, 고치지 않는 이유를 적는다.
- 고쳤으면 5번(테스트)을 다시 돈다.
- codex에게는 스크래치 복사본에서 쓰기 가능한 `GOCACHE`·`GOTMPDIR`로 `go vet`·`go test`를 돌리라고 요청한다. 샌드박스 때문에 돌리지 못하면 코드만 읽은 리뷰가 된다(M0·M1에서 17건 중 4건).
- **작은 뼈대 작업은 codex·fable 구현 리뷰를 건너뛴다.** 조건을 모두 만족할 때만: 분기가 있는 로직이 새로 생기지 않는다, 파일 쓰기·지우기·DB·보안 경로를 건드리지 않는다, 테스트가 아닌 변경이 50줄 안팎이다. 건너뛰면 계획에 `구현 리뷰 생략: 이유`를 한 줄 적는다. ponytail과 계획 리뷰는 건너뛰지 않는다.
  M0·M1의 뼈대 작업(M0 2·3번, M1 1번) 구현 리뷰 6건에서 한 리뷰어만 짚은 발견은 1개였다. 같은 작업의 계획 리뷰는 값을 했다(2026-09-27, 리뷰 68건 분석).

## 7. 완료

- `→ 확인:` 조건과 리뷰 지적이 모두 정리됐으면 `TASKS-Mn.md`의 항목을 체크한다.
- 새로 생긴 결정은 DECISIONS에, 미룬 일은 TODO에 적는다.
- 커밋한다. 커밋 메시지에 공동 작성자 표시를 붙이지 않는다.

## 사람 판단이 필요할 때 — 멈추고 묻는다

아래 경우에는 진행하지 않고 멈춘다.

- 결정(DECISIONS)에 없는 선택이 필요하거나, 결정과 부딪힌다
- 리뷰어끼리 의견이 갈리는데 결정·원칙으로 정해지지 않는다
- 작업 범위가 커지거나 마일스톤 순서를 바꿔야 한다
- 되돌리기 어렵거나 밖으로 나가는 일: push, 원격 변경, 파일·이력 삭제, 새 외부 의존 추가
- 같은 문제로 세 번 시도해도 풀리지 않는다

물을 때는 이렇게 한다.

- 무엇이 막혔는지 한두 줄
- 선택지 2~4개와 각각의 대가
- 추천 하나와 그 이유

답을 받으면 결정은 DECISIONS에 적고 루프를 이어 간다.
