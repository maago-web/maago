### 태그와 SQL의 기호

한 기호는 한 뜻만 가진다.

| 기호 | 뜻 | 쓰는 곳 |
|---|---|---|
| `,` | 옵션 구분 | 태그 |
| `'…'` | 문자열. 안의 `'`는 `''` | 태그 |
| `(a,b)` | 묶음 | 태그의 복합 제약 |
| `/` | 선택지 | 태그 `choices=draft/published`, SQL 파일 머리 `-- param: sort latest/amount` |
| `:이름` | 값 바인딩 | SQL |
| `{ }` | 줄어들 수 있는 곳 | SQL(`WHERE { }`, `SET { }`, `{조건}`) |
| `&` `\|` `!` `=` | 조건의 AND · OR · NOT · 같음 | SQL `{조건}` 안 |
| `?` | 없을 수 있다 → 포인터(없음 = `nil`) | SQL 파일 머리(`param: status?`, `column: author_name?`) |

**SQL 규칙 5개**

1. 파일 하나에 쿼리 하나. 머리에 이름·결과·파라미터를 선언하고, 없어도 되는 값에는 `?`. 결과 타입은 D-23.
2. 값은 `:이름`. 슬라이스는 원소마다 자리표시로 펼친다. 컬럼·테이블 이름은 바인딩하지 않는다.
3. 줄 머리의 `{조건}`을 만족할 때만 그 줄이 들어간다. 조건은 `이름`, `이름=값`, `!이름`을 `&` 또는 `|` **한 종류로만** 잇는다. 섞기·괄호 금지. 더 복잡한 조건은 Go에서 bool로 계산해 넘긴다.
4. `WHERE { }`와 `SET { }` 안에서만 앞의 AND/OR와 끝의 쉼표를 정리하고, 비면 절을 없앤다(`SET`은 비면 오류).
5. 생성기가 모든 조합을 커버해 연습용 DB에 prepare한다. 생성 오류: `SELECT`가 아닌 문장의 빈 WHERE, 라벨이 보장하지 않는 선택 파라미터 사용, 선언과 다른 결과 컬럼.

```sql
-- name: SearchOrders :many OrderSummary
-- param: status?    string
-- param: from?      time.Time
-- param: to?        time.Time
-- param: sort       latest/amount
-- param: limit      int64
SELECT id, status, amount, created_at FROM orders
WHERE {
  {status}          AND status = :status
  {from & to}       AND created_at BETWEEN :from AND :to
  {!status}         AND status <> 'deleted'
}
ORDER BY
  {sort=latest}     created_at DESC
  {sort=amount}     amount DESC
LIMIT :limit
```

검토하고 버린 것: `:x?` 자동 제거(위치마다 뜻이 달라진다), 줄 뒤 주석 조건(주석이 동작을 바꾼다),
`[[ ]]`(PostgreSQL 배열과 겹친다), 정적 SQL만(백오피스 검색 화면을 못 쓴다).
